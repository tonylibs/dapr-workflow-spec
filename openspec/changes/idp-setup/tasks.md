- [x] 3.3 Confirmed via a standalone smoke-test chart (isolated copy of `_helpers.tpl` + these templates, run through `helm template` outside the sandbox's network restriction) that the admin-credentials Secret's plaintext password and the config Secret's decoded `staticPasswords[].hash` are derived from the same generated value in a single render pass. **Design correction made during implementation**: `include` is not memoized in Helm — the originally planned "call the same named template from both files" would silently call `randAlphaNum` twice per render, producing two *different* passwords whenever `lookup` finds nothing (i.e. every `helm template`, and every real first `helm install`). Fixed by computing the password once as a `$password` variable in a single template file and passing it explicitly into both renders; verified with `bcrypt.checkpw` in Python against the rendered output. design.md's D2/D3 and this file's task 2.2/3.1 text were updated to match.
